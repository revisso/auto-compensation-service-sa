# Функциональные требования

Функциональные требования описывают, что должна делать Compensation Service. Каждому требованию присвоен уникальный идентификатор.

Основа: [Бизнес-требования](01-business-requirements.md), [Use Cases](use-cases.md), [Пограничные ситуации](edge-cases.md).

### Приём и проверка заявки

| ID | Требование |
|---|---|
| FR-01 | Система принимает заявку на недовоз с идентификатором заказа, списком товаров и причиной обращения |
| FR-02 | Система проверяет статус заказа и срок подачи заявки. Если с момента доставки прошло более 86 400 секунд, новая заявка не создаётся |
| FR-03 | Система проверяет, есть ли уже заявка по этому заказу. Если есть, возвращает её текущий статус |
| FR-04 | Для MISSING_ITEM и ORDER_NOT_RECEIVED фотография не требуется. Для QUALITY_ISSUE она обязательна, когда этот тип инцидента будет включён в систему |

### Расчёт и принятие решения

| ID | Требование |
|---|---|
| FR-05 | Система получает из Order Service состав заказа, цены товаров, скидки и способы оплаты |
| FR-06 | Система рассчитывает компенсацию с учётом скидки и стоимости недовезённых товаров |
| FR-07 | Система распределяет возврат между способами оплаты: сначала на карту, затем баллами |
| FR-08 | Система проверяет участие пользователя в пилоте, состояние выключателя и доступность месячного бюджета. Резервирование бюджета выполняется атомарно |
| FR-09 | Автоматическое одобрение возможно при сумме до 1500 рублей включительно и Trust Score не ниже 60 |
| FR-10 | Если Antifraud Service не отвечает в течение 2000 мс или возвращает ошибку, заявка передаётся на ручную проверку |

### Ручная обработка и выплата

| ID | Требование |
|---|---|
| FR-11 | При невозможности автоматической обработки система передаёт заявку в L2 вместе с причиной эскалации, данными заказа и расчётом компенсации |
| FR-12 | Оператор L2 может одобрить или отклонить заявку. При отказе он обязан указать причину |
| FR-13 | При ручном одобрении сумма и способ возврата рассчитываются по тем же правилам, что и при автоматической обработке |
| FR-14 | Система предотвращает повторную выплату по одной заявке, в том числе при повторных запросах и дублирующих вебхуках |
| FR-15 | При отказе банка система выполняет до трёх повторных попыток с тем же ключом идемпотентности. После четырёх неудачных попыток заявка передаётся в L2 |
| FR-16 | Если подтверждение выплаты не получено в течение 15 минут, система запрашивает статус платежа. До получения результата повторная выплата не запускается |

### Уведомления и дополнительные сценарии

| ID | Требование |
|---|---|
| FR-17 | Система уведомляет пользователя о результате обработки заявки. Повторные события не должны приводить к повторной отправке уведомления |
| FR-18 | Система обрабатывает подтверждённое событие опоздания из логистической системы. При задержке более 30 минут пользователь получает промокод на 10%, но не более 1000 рублей |
| FR-19 | Система не допускает повторную выдачу промокода по одному заказу. Выдача промокода не создаёт заявку на денежную компенсацию |
| FR-20 | Система предоставляет данные для расчёта Auto-resolution rate и Abuse Rate, а также формирует случайную выборку из 5% автоматически одобренных выплат для аудита |
