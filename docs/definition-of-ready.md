# Definition of Ready

Definition of Ready (DoR) определяет, достаточно ли проработан эпик «Автоматические компенсации», чтобы передать его в разработку.

Перед началом разработки должны быть выполнены следующие условия.

**Бизнес-контекст**

- Описана проблема и цель проекта.
- Определены границы первой версии.
- Отделены функции первой версии от задач следующих итераций.

**Требования**

- Пользовательские истории имеют ID и приоритеты.
- Для историй определены критерии приёмки Given-When-Then.
- Бизнес-правила не противоречат друг другу.
- Таблица решений покрывает основные варианты обработки заявок.
- Для пограничных ситуаций определено ожидаемое поведение системы.

**Сценарии и расчёты**

- Описаны UC-01, UC-02 и UC-03.
- Для каждого сценария определены основной и альтернативные потоки.
- Зафиксированы правила расчёта компенсации и распределения скидки.
- Подготовлены числовые примеры.
- Описан возврат при оплате картой и баллами.

**Функциональные требования**

- Каждое FR имеет уникальный идентификатор.
- Требования связаны с бизнес-правилами и Use Cases.
- Для требований определён способ проверки.
- Нет противоречий между требованиями.

**Интеграции**

- Определены данные, необходимые от Order Service.
- Описано взаимодействие с Antifraud Service.
- Зафиксированы ожидания от Payment Service и Loyalty Service.
- Определены данные для передачи заявки в Support CRM.
- Открытые вопросы и неизвестные контракты зафиксированы, назначены ответственные за их уточнение.

**Согласование**

- Определены приоритеты Must, Should, Could и Won't.
- Допущения, влияющие на расчёт и принятие решений, выделены отдельно.
- Критерии приёмки позволяют проверить результат без дополнительных пояснений.
- Участники проекта одинаково понимают объём первой версии.

Эпик готов к разработке, когда обязательные условия выполнены, требования понятны и проверяемы, а открытые вопросы не мешают реализации первой версии.
